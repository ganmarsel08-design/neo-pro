### Как теперь работает диктовка (PR #6)
- Ребёнок определяется автоматически, только если фамилия как в карточке (или номер бокса) стоит в начале фразы и подходит ровно одному ребёнку.
- «Сидорова:» с двоеточием — явный заголовок. Следующие фразы без фамилии относятся к нему, такие строки подсвечены.
- Ребёнок не выбирается автоматически, если во фразе несколько детей, у двойни нет номера или фамилии совпадают (Иванов и Иванова). Строка остаётся без ребёнка.
- Время переносится только на следующую фразу того же ребёнка. В остальных случаях ставится текущее время. Оба случая подсвечены жёлтым.
- Строки без ребёнка можно разом отнести к одному ребёнку кнопкой «Отнести все к …».
- Перед записью нужна отметка «Проверил детей, время, препараты и дозы».

## 3. Архитектура следующего этапа

Приложение не переписывается. Новые части — отдельные модули в `src/modules/`, данные — в `data/`. Каждый шаг — отдельная ветка и PR с тестами.

### 3.1 Клиническая память ребёнка (основа для остального)

Сейчас данные лежат в трёх местах: текст дневников (`k.days`), журнал смены (`k.log`) и поля карточки. Получить из них «что сейчас с ребёнком» можно только из текста.

**Предлагается** журнал событий `k.ev[]`. Записи только добавляются, старые не меняются:

```
{ id, t: время события, at: время записи, dev: устройство, by: автор,
  type: 'resp' | 'feed' | 'rx' | 'rxoff' | 'lab' | 'dx' | 'proc' | 'state' | 'task' | 'doc' …,
  data: { … структурированные значения с единицами … },
  src: 'dictation' | 'express' | 'manual' | 'nurse',
  st: 'draft' | 'confirmed' | 'signed',
  repl: id заменяемой записи (исправление — новая запись, старая видна в истории) }
```

- **Текущее состояние** не хранится, а вычисляется из событий: респираторная поддержка, кормление и объёмы, инфузии, препараты с датой начала, диагнозы, открытые задачи.
- **Подписанный дневник** — тоже событие `doc` с текстом. Правка создаёт новую версию, старая остаётся.
- **Синхронизация**: объединение событий по `id`, а не замена карточки. Две записи из разных устройств сохраняются обе. Если два устройства правили один и тот же интервал дневника, сохраняются оба варианта с пометкой «конфликт — выберите».
- **Хранение**: история — в IndexedDB, в localStorage — только активные дети и настройки. Выписанные уходят в архив: файл и облако.
- **Переход**: `k.log` и `k.days` остаются. События пишутся параллельно, старые поля читаются как раньше.

### 3.2 Черновики дневников каждые 3 часа

Черновики не пишутся в фоне по таймеру. Черновик собирается, когда врач открывает интервал. Если приложение открыто на границе интервала, черновики готовы заранее.

- Источники: последний подписанный дневник, события за интервал и текущее состояние из памяти.
- Без изменений — «прежний», как в образцах отделения. Новые события — фразами с временем. Чего нет — «___».
- Черновик никогда не подписывается сам. Подписать можно после просмотра, по одному ребёнку.
- Утренний дневник — развёрнутый. Остальные — краткие. Гидробаланс — в последнем интервале. Это уже сделано в экспресс-дневнике и переносится.

### 3.3 Диспетчер дежурства

Один экран «Что осталось»: строка — ребёнок и дело, сверху — ближайшее по сроку.

- Неподписанные черновики по интервалам.
- Задачи со сроком: назначенные врачом и предложенные правилами, например «СРБ через 18–24 ч после начала АБТ». Предложение становится задачей только после нажатия врача.
- Отличия от протокола РК без причины.
- Записи «не сохранено» и черновики диктовки, которые не записаны.
- Из этого же списка собирается текст передачи смены.

### 3.4 Карточка ухудшения

Одна кнопка в карточке ребёнка и на главном экране.

1. Сразу фиксируется время.
2. Признаки выбираются нажатием: SpO₂↓, брадикардия, апноэ, гипотензия, судороги, вздутие…
3. Для ИВЛ открывается проверка DOPE. Она уже есть в приложении.
4. Действия записываются с временем.

На выходе получаются запись об ухудшении в дневник, задача «повторная оценка через N мин» и событие в памяти ребёнка. Связанные карточки заболеваний (РДС, сепсис, НЭК) предлагаются ссылками. Решение о лечении остаётся за врачом.

### 3.5 Экспресс и экспертный режим карточек заболеваний

- **Экспресс** (по умолчанию): тактика одним нажатием, одна строка в дневник, ссылка на протокол РК.
- **Экспертный**: источники разных стран, дословные цитаты протоколов РК, расхождения, обоснование.
- Режим задаётся в настройках, в каждой карточке его можно открыть вручную. У каждого правила виден статус: кандидат или утверждено.

### 3.6 Общий реестр клинических знаний (с «Антидефектом»)

Отдельная папка или репозиторий `neo-knowledge`, из которого читают оба приложения:

- `protocols/` — 29 протоколов РК. Не меняются, проверяются по хэшу.
- `rules/` — правила «Антидефекта» со статусом `кандидат | утверждено | отменено`, автором утверждения и датой. Импорт скриптом, репозиторий «Антидефекта» только читается.
- `sources/` — зарубежные источники и проверенные цитаты.
- Номер версии реестра записывается в каждую подсказку и каждый подписанный дневник. Так видно, по каким правилам писалась запись.
- Проверка при каждом PR: цитаты дословны (`check-quotes.js`), протоколы не изменены (`verify.py`).

## 5. Критерии приёмки

**Общие для каждого PR**
- Тесты на синтетических данных проходят, ошибок в консоли нет.
- `verify.py`: протоколы совпадают байт в байт. `check-quotes.js`: 0 цитат не найдено.
- Не появилось ни одного значения, которого нет в событиях или прошлом дневнике (автотест на «выдуманные» числа).
- Записано время на типовые сценарии до и после. Если время выросло — PR не принимается.

**По этапам**

| Этап | Критерий |
|---|---|
| Хранилище | 60 синтетических детей × 60 суток сохраняются и открываются. При переполнении — предупреждение, а не тихая потеря. Архив открывается из файла |
| Память и синхронизация | Тест двух устройств: правки обоих сохраняются. Отстающие часы ничего не стирают. Правка дневника создаёт версию, старая видна |
| Черновики | Черновик интервала готов меньше чем за 1 с. Каждое число в нём прослеживается до события. Подписать без открытия нельзя. Цель пилота (гипотеза, проверить замером) — типовой дневник 1–2 мин |
| Диспетчер | Все неподписанные черновики, задачи со сроком и необоснованные отличия видны в одном списке. Передача смены собирается из него без ручного набора |
| Ухудшение | От нажатия до записи с временем — не больше 3 нажатий. Задача повторной оценки создаётся автоматически |
| Режимы | В экспресс-режиме карточка с типовой тактикой — 1–2 нажатия |
| Реестр | Подсказка и дневник хранят версию реестра. Правило-кандидат не блокирует запись. Утверждённое правило показывает автора и дату |

**Как измерять время.** В приложение встраивается локальный счётчик: время от открытия дневника до подписи и число нажатий. Данные остаются на телефоне, врач видит свою статистику. Без замера утверждать экономию нельзя.
